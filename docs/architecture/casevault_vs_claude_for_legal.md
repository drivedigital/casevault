# CaseVault vs. Claude for Legal: Comparative Architecture & Roadmap

This document captures the comparative evaluation of **CaseVault** against Anthropic's [**`claude-for-legal`**](https://github.com/anthropics/claude-for-legal) reference architecture.

---

## 1. Paradigm Comparison: Workflow Harness vs. Deterministic Legal Proof Graph

| Dimension | `anthropics/claude-for-legal` | `CaseVault` |
| :--- | :--- | :--- |
| **Core Architecture** | **Ephemeral Agentic Harness & Skill Plugins** | **Deterministic Proof Graph & Legal Operating System** |
| **Primary Interface** | Conversational chat, Claude Code CLI, slash commands | Dedicated Next.js 14 Web Workspace with Dark Glassmorphism |
| **Data Representation** | Flat Markdown files (`matter.md`), YAML logs (`_log.yaml`) | Relational database models (Postgres / Cloudflare KV) |
| **Evidentiary Floor** | Soft prompt instructions with inline tokens (`[CITE]`, `[VERIFY]`) | Programmatic review state gates (`proposed` $\to$ `accepted`) |
| **Burden Evaluation** | Qualitative LLM textual synthesis | Algorithmic point calculations & conflict detection |
| **Auditability** | Append-only markdown log (`history.md`) | Cryptographic immutable ledger (`ledger_entries`) |

* **`claude-for-legal`** treats the LLM as the operating environment. Documents and facts are ephemerally loaded into Claude's 200k token window, and deliverables (`.docx`, `.csv`, markdown tables) are generated on demand. It lacks an underlying relational database, persistent multi-user concurrent state, or deterministic calculation guarantees.
* **`CaseVault`** treats the LLM as an extraction engine while human counsel operates inside a **deterministic proof graph**. A legal claim cannot transition to `proven` unless supporting facts have been reviewed and accepted by counsel, and every fact remains tied to a cryptographically hashed source exhibit (`SHA-256`) with page and line boundaries.

### Key Distinctions
1. **Mathematical Burden Rollup**:
   - `CaseVault` algorithmically scores claim element support (`support_points`, `adverse_points`), deriving statuses (`proven`, `partially_supported`, `unsupported`, `conflicted`).
   - `claude-for-legal` relies on LLM qualitative narrative generation.
2. **Review Floor Invariant**:
   - In `CaseVault`, facts generated by AI remain in `review_state = proposed`. The API rejects linking unreviewed facts to claims or events with HTTP `409` or `422`, guaranteeing that AI drafts never distort the official record until an attorney calls `approveFact`.
3. **Multi-Matter Graph Topology**:
   - `CaseVault` features a first-class `MatterLink` schema (`consolidated`, `related_proceeding`, `advisory`), enabling interconnected proceedings (e.g., linking the *Part 19* Article 81 guardianship proceeding to the *230 CPS* Housing Part dispute and the *510 W 42* commercial hotel action).

## 3. Actionable Polish Roadmap for CaseVault

1. **Phase 1: Legal Research & Docket MCP Integration**:
   - Build MCP client gateways to CourtListener and Trellis for automated citation verification and negative treatment tracking.
   - Ingest `element-templates.md` from `claude-for-legal` to expand CaseVault's `claim_templates` library.
2. **Phase 2: Autonomous Intelligence & Background Watchers**:
   - Implement scheduled docket watchers for NYSCEF / PACER to auto-ingest new filings into the `/ai-review` queue.
   - Build automated exhibit gap detectors (flagging elements relying solely on testimony or conflicted evidence).
3. **Phase 3: Verified Drafting Studio (`/drafting`)**:
   - Enable statement-of-facts generation that draws **exclusively** from accepted facts with automated exhibit pin-cites (`Ex. 230-001 at 12`).
