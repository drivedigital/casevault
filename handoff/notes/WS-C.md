## Contract gaps (as-shipped delta; nothing silently adapted)

1. `GET /sources` filter parity (§3.2): server supports q, matter_id,
   source_type, evidence_review_status only. The UI's other four filters
   (source_status, ocr_status, included, excluded) run client-side until the
   BACKLOG filter-parity item lands — clearly commented in code.
2. List envelope `{items,total,limit,offset}` (§3.2) not shipped — plain array
   consumed as-is; pagination UI deferred with it (BACKLOG item exists).
3. `SourceDetailOut` (§3.2) not shipped — the detail view composes
   `getSource` + `listSourcePages` + `listSourceMatters` (works, one round-trip
   more than the contract shape).
4. `duplicate_of` is `{source_id, title, sha256}` vs contract `{id, title}` —
   UI uses `.title` only; tolerant of extra fields.
5. Include+exclude both-true returns **409** (DB CHECK) vs contract 422 — the
   UI never sends both; error copy mentions the server rule.

## Risks / follow-ups

- No browser in the sandbox: navigation/upload/download/linking were verified
  at the API-contract level + production build; a human click-through on the
  local stack is still worthwhile (screens are small).

  current scale, revisited with pagination.

  recovery scope; the endpoints are ready when Sprint 4/5 UI wants them.
